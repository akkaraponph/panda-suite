# Panda Brainstorm

Turn an idea into an evidence-based direction. An already agreed implementation
plan or a focused code explanation does not need this workflow.

## Inputs and workflow

Start with the problem or idea. Existing system evidence, user needs, business
constraints, budget, and technical limits are useful inputs. Inspect what is
available before asking for it. When a missing fact would change the direction,
ask a targeted question; otherwise state a working assumption.

1. **Understand the goal.** Identify who has the problem, the real task they
   struggle with, and the outcome that would make a difference. Separate a
   proposed solution (“microservice”) from the need (“manager decisions”).
2. **Identify constraints.** Establish current behavior, goals and non-goals,
   existing capabilities, operational limits, and business or UX obligations.
3. **Challenge assumptions.** Mark each material premise as supported, assumed,
   or unknown. Name the smallest useful experiment or evidence that could change
   the decision. Do not turn user confidence into technical evidence.
4. **Explore alternatives.** Include extending the current system or doing less
   when viable. Compare feasibility, user experience, delivery and maintenance
   effort, operational risk, reversibility, and business fit. Use only dimensions
   that distinguish the options; do not invent cost or delivery-time estimates.
5. **Recommend a direction.** Connect the recommendation to the goal and strongest
   constraints. Explain its trade-offs and the condition that would favor another
   option. If evidence is insufficient, recommend a bounded discovery step.

## Output and completion

Produce a problem statement, goals/non-goals, assumptions, realistic alternatives,
trade-offs, recommendation, risks, and open decisions. Scale the length to the
decision; a small idea can fit in a few paragraphs. The work is complete when the
user can assess the direction and knows which unanswered questions matter.

Brainstorming is analysis. Do not implement, change source, perform external
experiments with side effects, or generate an execution plan unless requested.
If a later activity is requested, hand off the chosen direction, constraints,
evidence, open decisions, and authorization. This skill works directly without
Panda Lead or another installed skill.

## Success discipline

Identify the requested outcome and evidence of completion. Continue useful authorized work, keep attention on current evidence, and compare the result with the outcome before reporting completion. State any remaining uncertainty or blocker. Kalāma: When a recommendation depends on an assumption, identify the evidence that would change it.
