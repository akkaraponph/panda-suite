# v1.5.1 — Specification output

Panda Spec saves new Markdown specifications under the active project's
.panda-suite/specs/YYYY-MM-DD-<topic>.md directory. Explicit output paths,
chat-only requests and explicit in-place edits take precedence.

Requests and source paths identify the project in a multi-project workspace.
Ambiguous project ownership or an ambiguous input/edit target triggers a
clarification before writing. Repository ignore and tracking policy governs
the output. Failed writes return the specification in chat.

## Verification

The evaluation record covers 22 observed runs with baseline, specialist and
routing controls. It retains the ambiguous-input failures and changed prompts.
A fresh run of the final clarification rule asked whether requirements.md was
an input or edit target and preserved the file byte-for-byte. See [evaluation evidence](../tests/results/spec-save/evaluation.md).

Skill validation, 30 tooling tests, host discovery and documentation checks pass.
The behavioral sample does not establish reliability across repeated runs.

## Compatibility and recovery

Users who need the former output location can supply an explicit destination.
There are no application migrations. To restore the previous instructions,
use v1.5.0. Existing specification files remain at their saved paths.
