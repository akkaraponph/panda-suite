# v1.5.0 — Panda Git

Panda Suite adds `panda-git`, bringing the catalog to 23 independent skills.

## Changes

- Diff-based Conventional Commit classification, scope, body, trailers and breaking
  impact, with user/repository convention overrides.
- Message-only, commit review and explicitly authorized execution modes. Existing
  authorization carries forward; unrelated edits/staging and normal hooks are preserved.
- Conditional guidance for inspection, branches, conflicts, history and recovery.
  Commit authority remains separate from push, tags, release and destructive actions.
- Lead routing, optional Craft/Refactor/Execute Git handoffs, English/Thai catalog,
  usage guide and generated documentation page.
- Twelve blind cases, a reproducible green-suite contract-gap fixture and compatible
  control. Initial trial failure is retained alongside the targeted correction.

## Verification and limits

See [Git contract and trials](panda-git.md) and the
[release verification](../tests/results/git/release-verification.md).
Baseline and specialist trials are small observations, not evidence of general
improvement. Most behavioral scenarios remain Not Run. Structural checks,
fixture checks and host discovery are reported independently.

## Compatibility and recovery

Portable and Claude manifests advance from 1.4.0 to 1.5.0. Existing names remain
supported. No application runtime, dependency or migration is added. Git is an
optional peer; standalone specialists continue working without it. Upstream
attribution and licensing remain unchanged.

Use v1.4.0 for the previous catalog. Preserve customized local skills before
replacement. Release publication does not by itself refresh plugin caches.
Documentation publishes from main through the existing GitHub Pages workflow.
