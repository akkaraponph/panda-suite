# v1.2.0 — Panda Refactor

Panda Suite adds `panda-refactor`, bringing the catalog to 20 independent skills.
It combines structural assessment, planning, incremental implementation and test
verification around preserving observable behavior and supported contracts.

## Changes

- Standalone refactoring workflow with optional Simplify, Plan, Execute, Test,
  Impact and Review guidance; no mandatory peer dependency or runtime.
- Analysis, design, plan, execute and review outcomes, with QUICK as a depth
  modifier. Read-only and planning-only requests retain their boundaries.
- Explicit invariants, baseline checks, meaningful incremental verification,
  source/requirement conflict handling and honest partial-verification reporting.
- Lead routing, English/Thai catalogs, usage examples and generated site guide.
- Nineteen evaluation scenarios and seven synthetic fixture directories, including
  paired green-suite defect/control cases and transaction/event boundaries.
- Reviewer-only contract checks and blind workspace-preparation regression.

## Verification and limits

Local checks for this release cover package metadata/references, all 20 standalone
installs, scenario coverage, upstream hashes, fixture distinctions, docs links,
and discovery through Codex and Claude. The [verification record](../tests/results/refactor/verification.md)
contains implementation results; release checks are recorded below.

Fresh model comparisons against baseline and existing workflows are **Not Run**.
No reliability, performance, token savings or universal equivalence advantage has
been established. The new skill is a focused entry point, not evidence that the
existing skills cannot refactor. Preserved source/requirement conflicts remain
explicit decisions rather than automatically authorized bug fixes.

## Compatibility and recovery

Existing skill names and invocation formats remain supported. Portable and Claude
manifests advance from 1.1.1 to 1.2.0. No new dependency, service, schema or data
migration is required. Upstream snapshots and attribution remain unchanged.
Users can return to v1.1.1 for the prior catalog; do not overwrite customized local
skills without preserving their changes. The existing upstream licensing status
in [source notices](../SOURCE_NOTICES.md) is unchanged by this release.
