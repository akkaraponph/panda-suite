# v1.1.0: security and performance

## Scope and contracts

This release adds [Panda Sec](../skills/panda-sec/SKILL.md) and
[Panda Perf](../skills/panda-perf/SKILL.md), bringing the catalog to nineteen skills.
Both follow the Suite's independently usable inputs/workflow/output/completion and
authorization contract with conditional skill-local references. Lead selects them
for dedicated audits and profiling; Review retains general changed-code defects,
and Simplify retains structural complexity analysis. No mandatory pipeline or
new runtime was added.

Sec addresses supported vulnerability reporting and dependency applicability:
rank severity separately from confidence, trace inputs and guards, inspect actual
resolved versions and advisory status, redact secrets, and preserve coverage gaps.
Perf addresses cost evidence and concrete optimization diffs: distinguish static
complexity from runtime measurements, preserve behavior, and report CPU/memory/I/O
trade-offs and workload limits. Read-only analysis does not authorize application
edits or external scans/load tests. Requested local optimization may be applied.

The design was checked against primary sources on 2026-11-08:
[OWASP Top 10:2025](https://top10.owasp.org/2025/0x00_2025-Introduction/),
[OSV source scanning](https://google.github.io/osv-scanner/usage/scan-source),
[Python profiling tools](https://docs.python.org/3/library/debug.html), and
[PostgreSQL EXPLAIN](https://www.postgresql.org/docs/current/using-explain.html).
OWASP is an awareness aid, not certification. Query execution and measurement
claims require actual evidence in the relevant environment.

## Existing-skill standardization

All skills retain their existing methods rather than adopting a repetitive
template. Shared validation checks names, metadata, manifests, standalone
references and scenario coverage. New checks reject missing/traversing fixtures,
empty task prompts, and unusable reviewer criteria. A tooling regression installs
every skill independently and verifies its local links. Review/Simplify and Lead
now state the new ownership boundaries.

The existing restore test edited adapted Debugger instructions instead of the
pinned vendor file. It now tests the pinned file; a separate regression confirms
local adaptations are preserved. The restore implementation was unchanged.
This fixes a demonstrated test defect rather than bypassing a failing gate.

## Behavioral trial protocol

Six `SEC-*` and six `PERF-*` reviewer cases are in the scenario catalog. Synthetic
fixtures include code weaknesses and effective controls, stale/withdrawn advisories,
failed scan evidence, integer/generic uniqueness contracts, retention policies,
tenant-filtered query batching and a tiny-table plan. No real credential, external
target, malicious pickle payload, or production database is involved.

User-authorized native task agents run fresh contexts per case/arm with inherited
model/settings, equivalent fixtures and access instructions, and no reviewer keys
or other answers. Baseline loads no skills; specialist loads an isolated instruction
copy; Lead loads only its routing instructions unless the task needs a specialist.
Only selected cases are model-tested. The model identifier, raw token telemetry
and independently enforced read isolation are not exposed by this native harness.
Task agents are instructed to remain within their supplied directories; all agents
share host access. Action logs are agent-authored records, not raw harness traces.
These limits prevent strong causal or statistical improvement claims.

## Results and verification

Fifteen actual model task trials and their artifacts are retained in the
[trial summary](../tests/results/v1.1.0/summary.md). Two Security cases and one
algorithm case have baseline/specialist pairs. Additional trials cover query
batching, applied optimization, memory, focused nonactivation and existing
Review/Write/Research behavior. Baselines also solved their tested cases;
comparative superiority is not established.

Independent checking found a query diff that required a nondefault zero-context
apply flag. The original failure was retained. Perf now checks its delivered
unified patch in a disposable copy; a fresh revised trial passed ordinary apply
and behavior checks. Memory/allocation costs and small-input timing regressions
remain in the reports instead of being discarded.

Retained model answers include unified diffs with space-only context lines. A
narrow `.gitattributes` rule preserves their exact evidence bytes without flagging
those lines as trailing whitespace; source and other whitespace checks remain on.

The concurrent documentation-site commit was integrated, preserving its links and
workflow; both new skills are in the site catalog. Its declared Markdown dependency
was installed only into the local development virtual environment for the build.

Untested cases remain Not Run; prepared workspaces are not model runs. Production
security scans, real credentials, real DB execution/plans, deployed memory/native
profiling and representative production speedups remain unverified. See the trial
summary for remaining coverage and exact model-comparison limits.
