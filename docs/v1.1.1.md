# v1.1.1 — Contract verification and recommendation discipline

This patch refines six existing skills. The catalog remains at 19 skills; no
runtime, dependency, specialist, or mandatory workflow was added.

## Changes

- **Lead:** distinguish exploration from artifact creation, check existing
  coverage before recommending additions, and reassess challenged recommendations.
- **Execute:** derive expected outcomes from requirements, probe uncovered
  acceptance rules, and distinguish green tests from complete acceptance evidence.
- **Review:** check changed behavior against the contract and whether existing
  assertions could detect a plausible violation, while retaining no-finding controls.
- **Brainstorm:** consider existing coverage and retaining the current approach;
  reconsider the premise before replacing a challenged suggestion.
- **Plan:** distinguish omitted, null, empty, and invalid inputs when their
  outcomes differ, and check whether the proposed boundary can deliver each error.
- **Skill Lab:** inspect existing corrections before adding more instructions;
  validate green-suite defect cases and correct controls without calling fixture
  checks model evaluations.

## Evidence and evaluation scope

Historical evaluation found implementations that passed supplied tests while
violating a stated requirement, an initial review that missed the same defect,
and an inconsistent proposed signature/error contract. Those original artifacts
remain unchanged in the [audit](../tests/results/2026-11-07/audit.md). Current
Execute and Plan already contained related corrections; this patch clarifies the
verification mechanism rather than presenting those historical defects as fresh
failures of current instructions.

The motivating conversation also showed premature drafting and unsupported
replacement recommendations. These observations justify narrow routing and
recommendation refinements; they do not establish causation or comparative gains.

Eleven new scenarios cover Lead overlap, exploration, challenged recommendations,
explicit creation, Execute acceptance coverage, Review defect detection and a
correct control, Brainstorm coverage and reassessment, Plan error boundaries,
and Skill Lab's handling of existing corrections. Reviewer expectations remain
outside task fixtures. Existing nonactivation cases remain in the catalog.

The new label-normalization fixture deliberately has a green supplied suite but
violates its duplicate-preservation requirement. Separate correct implementations
provide a review control. This is synthetic case validation, not a model trial.
The execution case receives only requirements, the faulty service, and supplied
tests; correct reference implementations are confined to the review fixture.

Fresh baseline and revised-skill model comparisons: **Not Run**. Token consumption,
time savings, and general behavioral improvement are unmeasured. No independent
task results are simulated or inferred from structural checks.

## Compatibility and recovery

Skill names, discovery descriptions, catalog size, invocation routes, and package
layout are unchanged. Portable and Claude manifests advance to 1.1.1. The changes
are instruction clarifications; they add no required infrastructure or data
migration. Existing users can restore the prior instructions by selecting v1.1.0.
An installed plugin cache is not modified by this source release.

The upstream Panda Debugger license uncertainty documented in
[source notices](../SOURCE_NOTICES.md) remains unresolved and unchanged.
